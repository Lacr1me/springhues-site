UNDER THE SURFACE

两端如何运转

WINDOWS

App 装配 WPF 窗口与系统服务，Presentation 维护界面状态，Core 承载解析、下载、媒体和作品库。MCP 以独立桥接进程接入。

ANDROID

应用层承接 Compose 界面、系统分享与网页浏览；核心模块分别负责平台解析、Room 数据、任务下载和媒体发布。系统调度承接后台执行。

WINDOWS

任务 JSON、下载临时文件与 HLS 检查点分别保存执行状态。暂停与恢复围绕同一任务进行，地址失效时按来源重新解析。

ANDROID

Room 保存任务，系统工作队列负责执行。暂停先落盘，恢复再调度；网络规则与启动对账让任务在允许的条件下继续。

WINDOWS

外部 AI 客户端通过随包 MCP 的 stdio 通道连接，再经当前用户命名管道访问应用。每次调用核对凭据与权限，复用已有下载服务。

ANDROID

手机端通过系统分享接收链接，由应用内任务操作和系统通知承接后续交互。本图中的 MCP 自动控制通路对应 Windows 随包组件。

WINDOWS

官网清单同时比较版本与分发身份，相同版本的新修订也能被识别。安装包下载校验后交给安装器，卸载默认保留个人数据和图库。

ANDROID

优先读取官网更新清单，网络或 HTTP 故障时再尝试 GitHub API。下载后校验包身份和安装签名，再进入系统安装流程。
