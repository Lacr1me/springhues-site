请直接开发并交付一个可在浏览器运行的纯体素 3D 交互网页，使用 React + TypeScript + Three.js / React Three Fiber。
项目名称：ASTERION · 阿斯忒里昂星港。
目标是"体素化的高端科幻巨构概念设计"：一座跨越数十公里、具有明确上下分层的轨道工业星港。建筑应表现出工业秩序、模块化工程逻辑、庞大的结构节距和基础设施尺度。
请完成真实三维场景、交互、必要验证和可运行交付，不要停留在方案、静态效果图或伪代码。
一、视觉方向
- 主色为银白、冷灰、深灰，使用少量但清晰可见的冷蓝能源灯光。
- 气质冷峻、理性、工业化，接近大型轨道基础设施和深空船坞的概念设计。
- 所有建筑、舰船和灯光实体都由轴对齐的盒状体素组成，斜撑使用阶梯式体素。
- 体素尺寸可以不同：大体素形成完整墙板、装甲板和承力梁，小体素形成肋条、仪器、接缝和设备。
- 大体量轮廓优先，随后是重复工程结构，最后才是表面细节。
- 保留深色设备峡谷、检修槽、开放骨架和层间空域，让建筑有真实厚度与内部空间。
- 避免可爱像素风、Minecraft 小建筑感、随机堆块、彩色棋盘表面以及没有结构逻辑的细节堆积。
- 不使用背景图片代替三维巨构，不引入平滑外部模型或贴图来掩盖体素结构。
二、总体尺度与布局
以星港中心为原点，整体大致覆盖：
X：−1900 至 +1900
Z：−1700 至 +1700
Y：−570 至 +620
概念比例可设为 10 米/模型单位。公里数仅用于模块资料，视觉尺度必须通过几何体量、重复节距、远近层次和舰船尺寸体现。
场景由以下结构构成：
1. 中央双脊主核
- 两座宽厚、分段收缩的能源与承力轴，中心位于 X≈−105 和 X≈+105。
- 主轴从下层约 Y=−338 延伸到上层约 Y=+505。
- 双轴之间保留开放设备峡谷，以多层维护桥连接。
- 外壳采用连续长装甲板，结合暗色凹槽、承力肋和少量能源节点。
- 主核必须有纵向体量，不能只是薄平台上的小塔。
2. 六座错层环形设施
   使用有明确内外边界的阶梯式八边形环，保留中央开口。
建议空间关系：
- 下层基座环：外半径约 460，Y≈−310 至 −254。
- 中层工业环：外半径约 410，Y≈−166 至 −88。
- 上层主核环：外半径约 338，Y≈48 至 125。
- 错位交通环：外半径约 510，Y≈−49 至 −22，可略微偏离中心。
- 下层能源环：外半径约 600，Y≈−447 至 −414。
- 高空指挥环：外半径约 242，Y≈552 至 578。
前三座环具有厚重装甲和设备城区；后三座更开放，以交通轨道、能源设施和框架为主。
环与环之间用桥梁、立柱、斜撑和悬挂设备连接，保留清晰的层间间隙。
3. 四条巨型主干与泊位臂
- 沿四个主要方向延伸，末端距离中心约 1440-1560。
- 不同主干位于略有差异的高度。
- 每条主干至少包含上层泊位、下层承力轨、侧壁、交叉桁架和开放中央槽。
- 两侧交替布置大型泊位指、装卸设施和重复工业单元。
- 通过几十组有规律的重复结构体现巨大尺度。
4. 八个外围港区
- 四座位于对角方向的开放式超级船坞，中心大致位于 X=±1040、Z=±965。
- 每座船坞约宽 410、长 640、高 280，由九组重复大型龙门架围成。
- 必须能看到船坞内部的空域、吊装设施和停靠舰船。
- 其余四个港区位于主干末端，包含轨道工厂、货运城、维护城区和舰队支援设施。
- 港区之间通过对角桁架和下层外围运输网络连接，形成完整工业系统。
5. 四座悬挂工业港
- 位于四个主干末端港区下方。
- 分别处于约 Y=−344、−418、−478、−382 的不同高度。
- 包含分离的制造舱、开放泊位、热交换翼和大型挂架。
- 用下层径向轨道连接中央能源环。
- 从侧面观察时，必须能清楚读出上层指挥、中层船坞、下层能源与悬挂港区的关系。
6. 分级舰队
- 至少八艘独立的大中型舰船，以及约 80 艘小型作业艇。
- 大型舰船长度约 140-230，中型舰船约 60-110，小型作业艇约 19。
- 舰船具有明确的船首、阶梯舰桥、装甲脊和独立推进舱。
- 大型舰船停靠在船坞内，同时安排一艘约 195 长的舰船悬停在前方空域，作为清晰的尺度参照。
- 舰船尺寸必须服从星港整体，避免舰船与整个港区一样大。
三、科幻感与照明
- 冷蓝灯光用于主核能源槽、环形设施边沿、主干导航线、悬挂能源舱和舰船推进器。
- 灯光应稀疏、成组、有功能位置，默认镜头下能辨认。
- 精细模式使用局部 HDR 辉光，银白建筑保持清晰轮廓。
- 使用主方向光、冷色补光和少量下层补光，使下层结构可读。
- 精细模式可使用静态结构阴影；静态场景不要每帧重新计算阴影。
- 背景为深色太空与克制的远景星光，突出建筑本身。
- 整体保持冷峻工业风格，避免满屏霓虹。
四、默认镜头与构图
默认镜头必须经过实际截图检查和调整。
以整体布局为上述尺度时，可从以下参数起步：
- 透视相机 FOV≈42°。
- 相机位置约 [1950, 925, 2500]。
- 观察目标约 [0, 35, 0]。
构图要求：
- 前景有大型船坞或港区，可以适度延伸到画面外。
- 中景主核具有明确的高度和厚度。
- 远景可见其他港区、主干和船坞。
- 上下层结构之间存在可读的空隙。
- 默认镜头突出体量和纵深。
- "整站总览"使用更远镜头，显示完整工程布局。
- 主核聚焦镜头展示双脊、环层、开放峡谷和能源设施。
- 移动端根据屏幕比例调整距离，避免主体被界面完全遮挡。
五、交互与界面
支持：
- 左键拖动旋转。
- 滚轮缩放。
- 右键拖动平移。
- 点击实际三维实体聚焦对应模块。
- 模块下拉选择与资料面板。
- 整站总览、中央主核、巨型泊位、舰队等镜头预设。
- 缓慢巡航镜头，用户拖动时立即中止巡航。
- 标签开关、精细/流畅模式、重置和全屏。
- 移动端触摸操作。
- 简洁中文操作说明和键盘快捷键。
界面采用克制的深色观测 HUD：
- 左上标题与简短介绍。
- 右侧紧凑模块资料。
- 底部镜头和操作按钮。
- 让三维场景占据主要视觉空间。
- FPS、实例数和绘制调用数必须来自实际渲染统计。
- 公里数及设施规格明确作为概念设计参数。
六、性能与实现
- 使用确定性程序生成建筑，保证重复加载布局一致。
- 使用 InstancedMesh 批量渲染装甲、发光体素和星空。
- 精细模式目标约 14万-20万个建筑与舰船实例。
- 流畅模式保留主要体量与骨架，省略小面板和仪器，目标约 6万-8.5万个实例。
- 将主要轮廓、承力结构与次级表面细节明确分层，降低画质不能破坏建筑布局。
- 静态实例矩阵只在初始化和画质变化时上传。
- 使用空间分区或其他加速结构进行体素拾取，避免鼠标操作时扫描全部实例。
- 流畅模式关闭昂贵后处理和阴影。
- 正确处理窗口变化、WebGL 不可用、上下文丢失和资源释放。
- 不依赖外部字体、CDN 或远程美术资源。
七、验证与交付
先检查当前工作区和可用开发环境，再直接实施。常规可逆步骤自行完成，不为每个阶段增加审批。
完成后：
1. 通过 TypeScript 检查和生产构建。
2. 在真实浏览器中检查默认画面、旋转、缩放、平移、实际实体点击、巡航、标签和画质切换。
3. 保存默认镜头与主核近景截图，检查建筑尺度、上下层关系和冷蓝灯光是否清晰。
4. 检查移动视口溢出和按钮可用性。
5. 如环境支持，导出内嵌脚本与样式的单文件离线 HTML，并实际打开验证。
6. 记录实际运行设备、实例数量和短时帧率；未测试的设备及长期稳定性要明确说明。
7. 交付源码、可运行产物、启动说明和必要验证记录。
8. 清理重复下载包、缓存、临时图片和部署中间文件；保留必要源码、产物和一份可恢复基线。
最终验收重点：
真实的多层空间关系、完整工业结构、默认镜头的震撼感、舰船尺度参照，以及可用的交互和性能。
